2.2 HTML-Semantik (2 Minuten)

Beschreibe den Unterschied zwischen den HTML-Elementen `<header> und <head>.`

 **`<head>`** 
- Gehört zum **HTML-Dokumentenaufbau** (Meta-Informationen).
- Enthält unsichtbare Metadaten für den Browser.
- Enthält keine sichtbaren Inhalte für den Benutzer.
- Wird im `<html>`-Element platziert.
- Typische Inhalte:
    - `<title>` (Seitentitel)
    - `<meta>` (Zeichensatz, Keywords, Beschreibung)
    - `<link>` (CSS-Dateien einbinden)
    - `<script>` (JavaScript einbinden)

 **`<header>`** 
- Gehört zum **sichtbaren Seiteninhalt** (Layout & Struktur).
- Enthält sichtbare Kopfzeilen (z. B. Titel, Navigation).
- Wird innerhalb von `<body>` verwendet.
- Enthält oft Überschriften (`<h1>`), Logos, Navigationsmenüs.
- Kann mehrfach in einem Dokument vorkommen (z. B. innerhalb von `<article>` oder `<section>`).

4.1 Node.JS http-Server (10 Minuten)

Gegeben ist ein Teil eines Node.JS-Servers mittels des http-Moduls. Ergänze im Folgenden den Server unter Beachtung folgender Punkte:
- Es dürfen keine weiteren Module importiert werden
- Clients senden HTTP-Bodys nur im x-www-form-urlencoded Format
- Der Server unterstützt nur die HTTP POST-Methode
    - Anfragen vom Client werden aber immer mit einem passenden Statuscode beantwortet
- Bei einer passenden Anfrage setzt der Server den Body zusammen und fügt den Wert der data-Eigenschaft vom Body als Objekt mit id der db Variable hinzu
    - Das Objekt soll nur hinzugefügt werden, wenn die data-Eigenschaft nicht undefined ist
    - Die ids der Objekte in der db Variable sind fortlaufend
    - Die id des neu erstellten Objekts wird dem Client zurücksendet


```js

const http = require('http');
const qs = require('querystring');

let body = '';
let db = [{ id: 0, data: '' }];

http.createServer((req, res) => {
    let method = req.method;
    //let params = url.parse(req.url, true).query;


    if (method === "POST") {
        let body = '';
        
        req.on('data', function (chunk) {
            body += chunk.toString();
        });

        req.on('end', function () {
            if (body.length > 0) {
                let newData = qs.parse(body);
                console.log('Request body:', body); 

                if (!newData.data ){  
                    res.writeHead(400); // 400 Bad Request
                    res.end();
                } else {
                    let newID = db.length;
                    db.push({ id: newID , data: newData.data });
                    res.writeHead(201, { 'Content-Type': 'application/json' }); // 201 Created
                    res.end(JSON.stringify({ id: newID }));
                }
            } else {
                res.writeHead(400);  // 400 Bad Request
                res.end();
            }
        });
    } else {
        res.writeHead(405); // 405 Method Not Allowed. Der Server unterstützt nur die HTTP POST-Methode
        res.end();
    }

}).listen(3000);

```

4.3 Express (6 Minuten)

Nutze das Express-Framework in Node.JS,  um einen Echo-Server auf Port 3005 zu implementieren. 
Der Express-Server soll den Body und die query-Parameter der Anfrage vom Client auslesen und diese im Antwort-Body mit dem Statuscode 200 als JSON-Objekt zurücksenden:
`{"body": <Body der Anfrage>, "query": <Query-Parameter der Anfrage>}`

Der Server soll alle HTTP-Methoden unterstützen sowie Anfrage-Bodys in den Formaten JSON und x-www-form-urlencoded. Alle notwendigen imports sind bereits gegeben.

```js
const express = require('express'); 
const bodyParser = require('body-parser');


const app = express();
const PORT = 3005;

app.use(bodyParser.json());
app.use(bodyParser.urlencoded({extended: true}));
app.use(express.json());

app.all((req, res) => {
    return res.status(200).send(`{"body": ${JSON.stringify(req.body)}, "query": ${JSON.stringify(req.query)}}`);
});


app.listen(PORT, () => {
    console.log(`Server läuft auf Port ${PORT}`);
});
```

4.4.2 Beschreibe kurz die Haupttechnologie die Sitzungsmanagement ermöglicht. (2 Minuten)

Client-basiertes Sitzungsmanagement
- Sitzungszustand wird in einem oder mehreren Cookies speichert - keine SessionId
- Übertragung des Cookies bei jeder Anfrage an den Server
- Aktualisierung des Cookies mit neuem Sitzungszustand bei jeder Antwort vom Server an den Client

In-Memory Sitzungsmanagement
- Sitzungszustand wird im Hauptspeicher des Servers gespeichert
- Cookies transportieren die SessionId
- Schnell, aber schlecht skalierbar da kein Load Balancing

Datenbank-basiertes Sitzungsmanagement
- Sitzungszustand wird in einem externen Session Store gespeichert
- Cookies transportieren die SessionId
- Beispiel: MongoDB


Authentication
- Credentials werden vom Client an den Server Base64-codiert und mit gesalzene hashed verschlüsselt  übertragen
- Base64: Codierung von Daten durch die Zeichen A-Z, a-z, 0-9, + und / sowie = am Ende
- Verschlüsselung des Passworts mit Hashfunktion mit Salz
